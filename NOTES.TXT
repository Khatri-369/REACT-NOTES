================================================================================
                           REACT CORE CONCEPTS & NOTES
================================================================================

1. WHAT IS REACT?
   - Open-source JavaScript library developed by Meta for frontend UI.
   - Component-based architecture: build complex UIs from isolated, reusable pieces.
   - Uses Virtual DOM for fast, optimized re-rendering (diffing & reconciliation).

2. COMPONENTS:
   - Independent, reusable pieces of code that return UI markup (JSX).
   - Can include HTML structure, CSS styling, and JS logic.
   - Re-renders automatically when state or props change.
   - CRUCIAL RULE: Component names MUST start with an Uppercase letter (PascalCase)!
     Example: <HelloMsg />, <AmazonCard />, <LikeButton />
     Reason: Lowercase tags (like <hellomsg />) are treated as native HTML tags and 
     React will not execute your component function.

3. JSX (JavaScript XML):
   - Syntax extension for JavaScript allowing HTML-like markup inside JS.
   - BABEL is the compiler that transforms JSX into regular JavaScript 
     (React.createElement).
   - Rules in JSX:
     * Must return a single root element or Fragment (<>...</>).
     * class in HTML       -> className in JSX
     * for in HTML         -> htmlFor in JSX
     * inline styles       -> style={{ backgroundColor: "#fff", padding: "1rem" }}
     * curly braces { }    -> Evaluates JavaScript expressions inside markup.
     * self-closing tags   -> <img />, <input />

4. REACT STRICT MODE (<StrictMode>):
   - Development tool to identify bugs and side-effects early.
   - In production, it does nothing and has zero performance overhead.
   - Why it renders 2 times in development:
     1. To check whether components are "pure functions" (no external side effects during render).
     2. To test useEffect cleanup functions by mounting, unmounting, and re-mounting.

5. PROPS (Properties):
   - Data passed from a parent component down to a child component.
   - Props are READ-ONLY (immutable); a child must never modify its received props.
   - Props flow unidirectionally (top to bottom).

6. PROPS DESTRUCTURING:
   - Instead of writing props.title, props.price:
     export default function Product({ title, price }) { ... }
   - Unpacks object keys directly in the function parameter list.
   - Supports default values: { title = "Default Item", price = 0 }

7. RENDERING LISTS WITH map():
   - Array.prototype.map() transforms each data item into a JSX element.
   - Returns a brand new array that React renders directly.
   - Always supply a unique "key" prop to each list element (e.g., key={id} or key={index}).
   - Why not forEach()? forEach() returns undefined, whereas map() returns the new array.

8. CONDITIONAL RENDERING & DYNAMIC STYLING:
   - Logical AND (&&): { price > 30000 && <p>5% Discount!</p> }
   - Ternary Operator: { isDiscount ? "Sale" : "Regular" }
   - Dynamic style objects:
     let styles = { backgroundColor: price > 30000 ? "#DCE5EC" : "#fff" };
     <div style={styles}>...</div>

9. MULTI-DIMENSIONAL DATA (2D ARRAYS):
   - Defining 2D array:
     let description = [
         ["Men's running shoes", "20% off"],
         ["Women's running shoes", "10% off"]
     ];
   - Accessing elements:
     description[0][0] -> "Men's running shoes"
     description[0][1] -> "20% off"

================================================================================
                    EVENTS, STATE & HOOKS (PART 2)
================================================================================

10. EVENT HANDLING IN REACT:
    - Events in React are named using camelCase (onClick, onMouseDown, onSubmit, etc.)
      instead of lowercase (onclick, onsubmit).
    - Pass function references, NOT function invocations:
      Correct:   <button onClick={handleClick}>Click</button>
      Incorrect: <button onClick={handleClick()}>Click</button> (invokes immediately on render)
    - Synthetic Event Object:
      * When an event fires, React automatically passes a synthetic event object (e / event)
        as an argument to the handler function.
      * It is a cross-browser wrapper around the browser's native event with the same
        interface (e.g. event.target, event.type).
    - Preventing Default Behavior:
      * Use event.preventDefault() to suppress native browser actions (e.g., preventing a
        <form> from refreshing the whole page on submission).
      Example:
        function handleSubmit(event) {
            event.preventDefault();
            console.log("Form submitted without page reload!");
        }

11. THE 3 PILLARS OF REACT:
    Every dynamic React application is built upon 3 foundational pillars:
    1) COMPONENT:
       - The structural building block of the user interface.
       - Encapsulates markup, style, and behavior.
    2) PROPS (Properties):
       - External inputs passed from parent to child.
       - Read-only / Immutable.
       - Enables component reusability.
    3) STATE:
       - Internal data owned and managed privately by the component.
       - Mutable via setter function.
       - Changes in state trigger automatic UI re-renders.

12. STATE IN REACT:
    - State is a built-in React mechanism used to store data or information about the
      component that can change over time based on user interactions or responses.
    - Why normal JS variables don't work for UI updates:
      * Regular variables reset every time the component function re-runs.
      * Changing a regular variable does NOT tell React to re-render the component.
    - When state changes:
      1. React re-executes the component function with new state values.
      2. It generates a new Virtual DOM tree.
      3. It diffs the new Virtual DOM with the previous one.
      4. It updates ONLY the modified parts in the real DOM (Reconciliation).

13. REACT HOOKS OVERVIEW:
    - Special functions introduced in React 16.8 that allow functional components
      to use state, lifecycle methods, and other React features.
    - There are roughly 15 built-in hooks (e.g., useState, useEffect, useContext,
      useReducer, useRef, useMemo, useCallback, etc.).
    - RULES OF HOOKS:
      1. Only call hooks at the TOP LEVEL of your component. Never inside loops,
         conditions, or nested functions.
      2. Only call hooks from React function components or custom hooks.

14. THE `useState` HOOK:
    - The most fundamental and commonly used hook in React.
    - Syntax:
        const [stateVariable, setFunction] = useState(initialValue);
    - Uses Array Destructuring:
      * index 0: The current state value.
      * index 1: An updater/setter function used to change that state and request a re-render.
    - Example (Toggle State):
        const [isLiked, setIsLiked] = useState(false);
        function handleClick() {
            setIsLiked(!isLiked);
        }

15. STATE UPDATER FUNCTIONS (DIRECT VS. CALLBACK PATTERN) & CLOSURES:
    - React state updates are asynchronous and batched for performance optimization.
    - Two ways to update state:
      1) Direct Assignment:
         setCount(count + 1);
         * Use when the new state does not depend on previous state updates happening in the same batch.
      2) Updater Callback Pattern:
         setCount((prevCount) => prevCount + 1);
         * MUST BE USED when the future value depends on the previous value!
         * React guarantees `prevCount` holds the latest pending state value.
         * Example: If you run setCount(count + 1) twice in one function, count only increases by 1
           because both read the same snapshot from the closure.
           If you run setCount((prev) => prev + 1) twice, it increases by 2!
    - Closures in React:
      * In JavaScript, a closure is when an inner function remembers variables from its outer scope.
      * Each render of a component has its own props, state, and event handlers.
      * Inside the event handler, variables like `count` capture the snapshot of that specific render.

16. LAZY INITIAL STATE (OPTIMIZING EXPENSIVE INITIALIZATIONS):
    - When state initialization involves a heavy computation or function:
      * Unoptimized: useState(RANDOM())
        -> RANDOM() will be invoked on EVERY single render, wasting CPU cycles, even though
           React only uses the result on the initial mount!
      * Optimized (Lazy Initial State): useState(RANDOM)
        -> Pass only the FUNCTION REFERENCE (without parentheses). React will execute it
           ONLY ONCE during the initial mount, skipping execution on subsequent renders.

================================================================================
               OBJECTS & ARRAYS IN STATE (COMPLEX STATE)
================================================================================

17. OBJECTS IN REACT STATE:
    - Initializing an object in state:
        const [moves, setMoves] = useState({ blue: 0, red: 0, yellow: 0, green: 0 });
    - State Immutability:
      * React detects state changes by comparing object references (shallow comparison).
      * Directly mutating properties (e.g., moves.blue += 1) DOES NOT change the object reference,
        so React will NOT re-render the component!
    - Updating Objects using the Spread Operator (...):
      * Always create a new object copying unchanged properties:
        setMoves((prevMoves) => {
            return { ...prevMoves, blue: prevMoves.blue + 1 };
        });
      * Why spread? `setMoves` replaces the entire object. Spreading copies over all other
        existing keys (red, yellow, green) so they don't get erased.

18. ARRAYS IN REACT STATE:
    - Treating Arrays as Immutable:
      * Standard mutating array methods (push, pop, splice, shift, unshift) should NEVER be used directly on state.
      * Always use non-mutating methods that return a new array (spread [...], filter, map, slice).

    - Common Array Operations in State (TodoList / LudoBoard pattern):
      1) ADDING an item (Spread Operator):
         setTodos((prevTodos) => [...prevTodos, newTodo]);

      2) DELETING an item (.filter()):
         setTodos((prevTodos) => {
             return prevTodos.filter((_, idx) => idx !== indexToDelete);
         });

      3) UPDATING ALL elements (.map()):
         setTodos((prevTodos) => {
             return prevTodos.map((todo) => todo.toUpperCase());
         });

      4) UPDATING A SINGLE element by index/condition (.map()):
         setTodos((prevTodos) => {
             return prevTodos.map((todo, idx) => {
                 if (idx === targetIndex) {
                     return todo.toUpperCase();
                 }
                 return todo;
             });
         });

      5) MARKING AN ITEM AS DONE / COMPLETE:
         - Method A (Storing JSX / Tag wrap):
           setTodos((prevTodos) => prevTodos.map((todo, idx) => idx === target ? <s>{todo}</s> : todo));

         - Method B (Best Practice: Array of Objects with boolean flag):
           State: [{ id: 1, task: "Buy Milk", isDone: false }]
           Update:
             setTodos((prevTodos) => prevTodos.map((todo, idx) => {
                 return idx === target ? { ...todo, isDone: !todo.isDone } : todo;
             }));
           Render:
             <span style={{ textDecoration: todo.isDone ? "line-through" : "none" }}>
                 {todo.task}
             </span>
